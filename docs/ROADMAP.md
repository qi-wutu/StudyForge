# Roadmap — StudyForge 从 V1 到 V2

> 一句话：
> **V1（当前）** 是"点哪用哪"的 Web 学习工具；
> **V2（规划）** 是"聊天就能学"的自然语言学习 Agent。

---

## 当前版本：V1（已发布）

### V1 是什么

导入学习资料 → 自动提取知识点 → AI 出题 → 自由回答 → AI 评分 + 指出缺失 → 薄弱分析 → 针对性回炉。

不是刷题工具，是 **AI 面试官 + 学习教练**。你像聊天一样回答，它像老师一样打分、写评语、告诉你哪里弱、给你找资料补。

### V1 已经具备的能力

- 资料导入 → LLM 提取知识点（BM25 语义去重）
- 混合检索（BM25 0.7 + bge-small-zh 向量 0.3，召回优先）
- AI 主观题出题 + 判分 + 评语 + 优缺点 + 缺失知识点
- LangGraph 条件边复习循环（interrupt + checkpointer）
- 双车道薄弱感知调度（2:1 交错，防止饿死）
- 轻量 ReAct — 节点内 LLM 自主搜索网络出题
- Agent Memory — 出题/判分时注入历史答题上下文
- 薄弱分析报告（统计 + LLM 报告 + 缓存）
- Benchmark 评测套件（93 题 × 三维度判分评测 + 检索 Hit@k/MRR 评测）
- Web UI（React 19 + TypeScript + Vite，亮/暗主题）

### V1.1（本阶段）— 自然语言交流入口

给 V1 加了一个"听得懂话"的皮层，让对话真正跑通：

- **对话框**（前端 Chat 页 + `POST /api/chat`）——自然语言入口，和按钮版页面并行
- **简易意图识别**（`nlu/`，规则优先）——8 类 intent：`exit_review / start_review / next / analyze / import / qa / answer / smalltalk`
- **复习语境消歧**——复习进行中，非命令的普通输入视为作答；明显提问则插话走问答
- **轻量问答子能力**（`qa_agent`）——"什么是 GMP 模型" → 混合检索已有资料 → grounded 回答
- 现有功能端点 / 复习图 / 存储全部复用，V1 核心零改动

### V1.2（本阶段）— 架构重构 · 子 Agent 化

把代码结构从"图 + service"重构成"**主 Agent 调度多个子 Agent**"，让架构长成能讲的多 Agent 故事：

- **4 个专职子 Agent** 各自独立成模块、接口可调用：
  - `agent/review_agent.py`（复习：LangGraph 调度/出题/判分 + `start/answer/next/exit` turn API）
  - `agent/import_agent.py`（导入：提取知识点 + BM25 去重 + embedding）
  - `agent/qa_agent.py`（问答：混合检索 + grounded 回答）
  - `agent/analyzer.py`（分析：统计 + LLM 报告）
- **主 Agent `agent/supervisor.py`**：识别意图 → 分发给上述子 Agent
- **拆掉上帝模块** `graph/node.py`：`get_llm()`/ReAct → `core/llm.py`，检索缓存 → `rag/retriever.py`；`graph/` 目录删除
- 复习图（LangGraph + interrupt + checkpointer）**原样保留**，只是迁进 ReviewAgent 内部；行为零回归（supervisor 分发冒烟结果与 V1.1 完全一致）
- service 层收敛为无状态读服务（session / stats）；所有 API 端点路径不变，前端零改动

一句话：V1.2 让"几个 Agent、各自干嘛"从纸面叙事变成**真代码结构**。但 supervisor 目前仍是 `if/else` 规则分发（supervisor 的"功能等同体"），**还不是真正的一张 LangGraph 主图**（interrupt 上移到主图边界，是 V2 核心）。

### V1 现在的交互方式

用户用**固定入口**驱动系统：

- 点「开始复习」→ 出题 → 回答 → 判分 → 下一题
- 点「导入」贴资料 → 提知识点
- 点「薄弱分析」→ 报告

LLM 在其中扮演的是**单点认知角色**——在出题、判分、提知识点、写分析报告这些环节里"思考/评分"，被写死在每个步骤里。

### V1 的局限

1. **路由是写死的**：控制流（何时调哪个节点）编码在 HTTP 端点和图边里，系统不"理解"用户想干什么。
2. **不能自然语言对话**：用户必须知道该点哪个按钮、贴哪个命令，走预设路径。
3. **LLM 只做单点推理**：它不参与理解用户意图，只负责每步的判断/打分。

换个说法：V1 是一个**很好用的工具**，但不是**能听懂你说话的 Agent**。

## 下一阶段：V2（规划中）

### V2 目标

从"点哪用哪"变成"**聊天就能学**"：用户用自然语言告诉系统想要什么，系统识别意图、自己决定去调用哪块能力。

> "帮我复习一下数据库的索引"
> "什么是 GMP 模型？"
> "我上次哪些知识点薄弱？"
> "把这篇文档导入进来"

——系统听明白你想干嘛，然后自己路由到复习 / 问答 / 导入 / 分析。

### V2 的核心特性

**1. 意图识别（Intent Recognition）**

- 用户自然语言输入 → 识别意图（复习 / 提问 / 导入 / 分析 / 搜索…）+ 抽取参数（知识领域、数量、话题）
- 单轮识别，结构化输出（意图 + 参数），交给后续调度

**2. 自然语言对话（Conversational Agent）**

- 入口从"固定端点/按钮"变成"对话框"：用户说什么都行
- 一个主图调度多个子图（复习图 / 导入图 / 分析图 / 问答图），按意图动态分发
- 多轮对话，而不是单次请求

**3. 多 Agent 编排**

- 主 Agent 理解意图，把任务交给对应子 Agent
- 每个子 Agent 专注于一件事，职责清晰、可独立测试
- 各子 Agent 复用 V1 已有的存储、检索、判分能力

### V1 vs V2 对比

| 维度 | V1（当前） | V2（规划） |
|---|---|---|
| 入口 | 固定端点 / 按钮 | 自然语言对话框 |
| 理解用户 | 不参与，LLM 只做单点思考+评分 | 意图识别理解用户想要什么 |
| 路由 | 写死的 HTTP 路由 / 图边 | 主图按意图动态分发 |
| 交互 | 点按钮 / 贴命令，走预设路径 | 聊天即学习 |
| Agent | 单 Agent，节点内轻量 ReAct | 多 Agent 编排 |

## 演进路径

按"先内后外、尽量复用 V1"的顺序推进：

1. **意图识别节点**：先做单轮意图识别，把"用户输入 → 结构化意图"打通（这是地基）。
2. **对话入口**：接一个自然语言入口，让意图分发跑通复习/导入/分析这几个已有子图。
3. **多 Agent 编排**：引入主图调度多个子图，Agent 职责清晰化。
4. **体验优化**（可与 2 并行）：复习改成"出一题 → 答一题 → 判一题 → 回到对话"，而不是一次跑完整个图。

**进度：**
- ✅ **V1.1** — 已把 1–2 用"规则版"跑通：`nlu/` 单轮意图 + 对话分发，复习/问答/导入/分析都能用自然语言触达。
- ✅ **V1.2** — 子 Agent 化：4 个专职子 Agent + supervisor 独立成模块，拆掉上帝模块 `graph/node.py`，`get_llm()`/ReAct/检索缓存落到 `core/` 与 `rag/retriever.py`。
- ⏳ **剩余差距**：(a) 把"规则 if/else 分发"升级成**真正的 LangGraph supervisor 图**（interrupt 上移到主图边界）→ V2 核心；(b) **LLM 辅助意图识别**（规则快路 + LLM 兜底）拿结构化 `{intent, params}` → **V1.3**。

> V1.3 见 [issue #2](https://github.com/qi-wutu/StudyForge/issues/2)。

V1 的存储（MySQL）、混合检索（BM25+向量）、判分、双车道调度、Agent Memory 全部**原样复用**，V2 是加一个"听得懂话"的皮层，不重造核心。
