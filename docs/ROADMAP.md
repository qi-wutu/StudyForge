# Roadmap — StudyForge 从 V1 到 V2

> 一句话：
> **V1（当前）** 已经从"点哪用哪"长出自然语言皮层（V1.1 对话入口 + V1.3 LLM 大脑），
> **V2（规划）** 是把它升级成一张真正的 LangGraph 主图（interrupt 上移到主图边界、多子图编排）。

---

## 当前版本：V1（已发布）

### V1 是什么

导入学习资料 → 自动提取知识点 → AI 出题 → 自由回答 → AI 评分 + 指出缺失 → 薄弱分析 → 针对性回炉。

不是刷题工具，是 **AI 面试官 + 学习教练**。你像聊天一样回答，它像老师一样打分、写评语、告诉你哪里弱、给你找资料补。

### V1 已经具备的能力

- 资料导入 → LLM 提取知识点（BM25 语义去重）
- 混合检索（BM25 0.7 + bge-small-zh 向量 0.3，召回优先）
- AI 主观题出题 + 判分 + 评语 + 优缺点 + 缺失知识点
- LangGraph 条件边复习循环（interrupt + checkpointer）
- 双车道薄弱感知调度（2:1 交错，防止饿死）
- 轻量 ReAct — 节点内 LLM 自主搜索网络出题
- Agent Memory — 出题/判分时注入历史答题上下文
- 薄弱分析报告（统计 + LLM 报告 + 缓存）
- Benchmark 评测套件（93 题 × 三维度判分评测 + 检索 Hit@k/MRR 评测）
- Web UI（React 19 + TypeScript + Vite，亮/暗主题）

### V1.1（本阶段）— 自然语言交流入口

给 V1 加了一个"听得懂话"的皮层，让对话真正跑通：

- **对话框**（前端 Chat 页 + `POST /api/chat`）——自然语言入口，和按钮版页面并行
- **简易意图识别**（`nlu/`，规则优先）——8 类 intent：`exit_review / start_review / next / analyze / import / qa / answer / smalltalk`
- **复习语境消歧**——复习进行中，非命令的普通输入视为作答；明显提问则插话走问答
- **轻量问答子能力**（`qa_agent`）——"什么是 GMP 模型" → 混合检索已有资料 → grounded 回答
- 现有功能端点 / 复习图 / 存储全部复用，V1 核心零改动

### V1.2（本阶段）— 架构重构 · 子 Agent 化

把代码结构从"图 + service"重构成"**主 Agent 调度多个子 Agent**"，让架构长成能讲的多 Agent 故事：

- **4 个专职子 Agent** 各自独立成模块、接口可调用：
  - `agent/review_agent.py`（复习：LangGraph 调度/出题/判分 + `start/answer/next/exit` turn API）
  - `agent/import_agent.py`（导入：提取知识点 + BM25 去重 + embedding）
  - `agent/qa_agent.py`（问答：混合检索 + grounded 回答）
  - `agent/analyzer.py`（分析：统计 + LLM 报告）
- **主 Agent `agent/supervisor.py`**：识别意图 → 分发给上述子 Agent
- **拆掉上帝模块** `graph/node.py`：`get_llm()`/ReAct → `core/llm.py`，检索缓存 → `rag/retriever.py`；`graph/` 目录删除
- 复习图（LangGraph + interrupt + checkpointer）**原样保留**，只是迁进 ReviewAgent 内部；行为零回归（supervisor 分发冒烟结果与 V1.1 完全一致）
- service 层收敛为无状态读服务（session / stats）；所有 API 端点路径不变，前端零改动

一句话：V1.2 让"几个 Agent、各自干嘛"从纸面叙事变成**真代码结构**。

### V1.3（本阶段）— LLM 大脑 · 通用 Agent 化

把 supervisor 从"规则路由器"升级成 **LLM 工具调用循环**——它现在真"听得懂"你在说什么：

- **`core/llm.py::run_agent()`** 通用工具循环：LLM 绑定一组工具，自主决定调哪个、可多轮往复、超轮强制收尾、工具异常不崩
- **`agent/tools.py::build_tools()`**：把 4 个子 Agent + 统计服务的能力包成 7 个可调用工具（开始复习 / 作答判分 / 退出复习 / 问答 / 薄弱分析 / 导入 / 通用搜索）
- **主 Agent `Supervisor.chat()` 重写**：确定性安全快路（退出/下一题/导入前缀，防误判 & 不花 LLM）→ 把**对话历史真正喂给 LLM** → 跑工具循环 → 由工具结果决定返回卡片
- **`nlu/intent.py` 退为安全快路**：8 类正则完整实现保留（`classify_intent`，测试锁定），只额外暴露 `fast_path_intent()` 拦截最确定的小撮命令
- **前端卡片加 LLM 前言气泡**：出题/判分/分析等卡片前先出一句自然语言，更有"聊天"手感
- 话题参数（如"复习数据库索引"里的"数据库索引"）**先识别、暂不落地**到出题范围
- 单测 29 条（13 意图 + 16 工具层/循环）；真机端到端验证「闲聊 → 出题 → 作答 → 插话提问 → 薄弱分析 → 导入 → 带记忆追问」全链路

一句话：V1.3 让 supervisor 从"背下来的路由表"变成**会看场景下命令的 LLM 调度器**——你说闲聊它陪聊，说"开始复习/考考我 GMP"它就自己调子 Agent 出题。离 V2 只差"用一张 LangGraph 主图 + interrupt 显式编排这套多轮调度"。

### V1 现在的交互方式

两条车道并行，数据完全共享：

- **对话（推荐）**：在「对话」页用自然语言说「开始复习」「什么是 GMP」「我哪里薄弱」「导入：xxx」，supervisor 的 LLM 会自己决定调哪个子 Agent、并带对话记忆
- **按钮页**：Dashboard / 复习 / 导入 / 分析 等原固定入口全部保留，行为与对话完全一致

LLM 的角色已从"单点认知"升级为**对话大脑**：它理解用户意图、决定路由（V1.3），同时出题/判分/提知识点/写报告这些子能力仍是各子 Agent 内部的 LLM 推理。

### V1 的局限（V1.3 之后剩什么）

1. ~~**路由是写死的**~~ → V1.3 已解决：路由由 LLM 工具循环决定（仅保留极少数确定性安全快路）。
2. ~~**不能自然语言对话**~~ → V1.3 已解决：有对话框 + 对话记忆，能聊、能边聊边学。
3. **还不是一张显式的 LangGraph 主图**：这套「LLM 决定 → 调工具 → 多轮」目前跑在 `run_agent()` 的命令式循环里，interrupt 没有上移到主图边界，多子图也没有在图上显式编排——这是 V2 的核心差距。

换个说法：V1.3 的 supervisor 已经**能听懂你说话的 Agent**；V2 是把它内部那套"决策 → 执行"显式画成一张可中断、可检查点的主图。

## 下一阶段：V2（规划中）

### V2 目标

从"点哪用哪"变成"**聊天就能学**"：用户用自然语言告诉系统想要什么，系统识别意图、自己决定去调用哪块能力。

> "帮我复习一下数据库的索引"
> "什么是 GMP 模型？"
> "我上次哪些知识点薄弱？"
> "把这篇文档导入进来"

——系统听明白你想干嘛，然后自己路由到复习 / 问答 / 导入 / 分析。

### V2 的核心特性

**1. 意图识别（Intent Recognition）**

- 用户自然语言输入 → 识别意图（复习 / 提问 / 导入 / 分析 / 搜索…）+ 抽取参数（知识领域、数量、话题）
- 单轮识别，结构化输出（意图 + 参数），交给后续调度

**2. 自然语言对话（Conversational Agent）**

- 入口从"固定端点/按钮"变成"对话框"：用户说什么都行
- 一个主图调度多个子图（复习图 / 导入图 / 分析图 / 问答图），按意图动态分发
- 多轮对话，而不是单次请求

**3. 多 Agent 编排**

- 主 Agent 理解意图，把任务交给对应子 Agent
- 每个子 Agent 专注于一件事，职责清晰、可独立测试
- 各子 Agent 复用 V1 已有的存储、检索、判分能力

### V1 vs V2 对比

| 维度 | V1.3（当前） | V2（规划） |
|---|---|---|
| 入口 | 对话框 + 固定按钮并存 | 对话为主，全能力可自然语言触达 |
| 理解用户 | LLM 读对话历史理解意图（V1.3） | 同左，意图/参数更结构化落地 |
| 路由 | LLM 工具循环动态决定（`run_agent` + `build_tools`） | LangGraph 主图按意图分发 + interrupt |
| 交互 | 聊天即学习（带对话记忆） | 同左，可中断、可检查点、可编排多子图 |
| Agent | 主 Agent（LLM 调度）+ 子 Agent（工具化） | 一张主图调度多个子图 |

## 演进路径

按"先内后外、尽量复用 V1"的顺序推进：

1. **意图识别节点**：先做单轮意图识别，把"用户输入 → 结构化意图"打通（这是地基）。
2. **对话入口**：接一个自然语言入口，让意图分发跑通复习/导入/分析这几个已有子图。
3. **多 Agent 编排**：引入主图调度多个子图，Agent 职责清晰化。
4. **体验优化**（可与 2 并行）：复习改成"出一题 → 答一题 → 判一题 → 回到对话"，而不是一次跑完整个图。

**进度：**
- ✅ **V1.1** — 已把 1–2 用"规则版"跑通：`nlu/` 单轮意图 + 对话分发，复习/问答/导入/分析都能用自然语言触达。
- ✅ **V1.2** — 子 Agent 化：4 个专职子 Agent + supervisor 独立成模块，拆掉上帝模块 `graph/node.py`，`get_llm()`/ReAct/检索缓存落到 `core/` 与 `rag/retriever.py`。
- ✅ **V1.3** — 3 走"LLM 工具调用循环"版：`run_agent()` + `build_tools()` 把子 Agent 能力工具化，supervisor 的 LLM 读对话历史自主决定路由；规则 `nlu/` 退为确定性安全快路（原"结构化 `{intent, params}` 单轮识别"方案被工具循环取代，见下）。
- ⏳ **剩余差距**：把 supervisor 内部那套"LLM 决策 → 调工具 → 多轮"升级成**真正的 LangGraph supervisor 主图**（interrupt 上移到主图边界、多子图图上编排）→ V2 核心。

V1 的存储（MySQL）、混合检索（BM25+向量）、判分、双车道调度、Agent Memory 全部**原样复用**，V2 是"把决策层显式画成一张主图"，不重造核心。
