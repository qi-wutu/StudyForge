# 知识点去重策略

## 问题

用户导入多份学习资料（例如"Go 八股文第1篇"和"Go 八股文第2篇"），两篇都可能提到 GMP 模型。LLM 提取知识点时，可能产出高度相似的内容：

```
知识点 A：Go GMP 模型 — G、M、P 的作用
知识点 B：GMP 调度原理 — goroutine 与线程的关系
```

都存进数据库显然不对——复习时会重复考察同一块知识，浪费用户时间，也暴露系统设计缺陷。

## 分析

这个问题的本质是：**LLM 提取是独立的，不同资料互不知情**。planner 节点没有跨文档的记忆，每份资料来了就是"从零提取"。

解法可以有多个层次，从简单到复杂：

## 方案对比

### 方案一：Prompt 层去重（v0 采用）

提取知识点前，先查数据库已有知识点的标题列表，拼进 prompt 让 LLM 自行判断。

```
已有知识点：
  - Go GMP 模型
  - channel 底层原理

要求：不要提取与以上重复或高度相似的内容
```

**优点：**
- 零额外代码，不依赖第三方
- LLM 本身理解"重复"的概念，判断准确率可观
- 每多一份资料等于多一次去重温，不会退化

**缺点：**
- 标题列表长了会占 token（几百个时成本明显）
- LLM 的判断不是 100% 可靠，偶尔漏重或误杀

### 方案二：BM25 语义去重（后续迭代）

用项目自带的 `rag/bm25.py`（手写 BM25 检索），将新提取的知识点与已有知识点做文本相似度比较，超过阈值则合并或跳过。

```
新知识点：Go GMP 模型中的 P 是什么
  ↓ BM25 检索
命中：Go GMP 模型（相似度 0.87）
  → 跳过插入，或合并到已有知识点
```

**优点：**
- 精确可控，阈值可调
- 不消耗 LLM token
- 面试时可以展开讲 BM25 公式

**缺点：**
- 需要维护 BM25 索引
- 中文分词（bigram）可能不如 LLM 理解准确

## 决策

v0 先用方案一（prompt 层去重），理由：

1. 成本最低，改一个 prompt 就行
2. v0 数据量小，token 开销不敏感
3. 核心逻辑还没跑通前，不值得优化非关键路径

等后面导入的资料多了、token 成本开始疼了，再上方案二。两个方案不冲突，可以叠加。

## 面试怎么讲

> "知识点去重我分了两层。第一层在 prompt 里传已有标题，让 LLM 自己判断，几乎零成本。第二层用自实现的 BM25 做语义相似度去重，精确控制阈值。目前跑的量用第一层就够了，BM25 那套随时能加上。"

两层都提到，说明不是碰巧解决了一个问题，而是设计了分层防御。
