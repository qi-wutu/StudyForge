# 双车道调度策略 — 解决"薄弱扩散会导致重复考同一块"的问题

## 背景

实现薄弱分析后，下一步是让 scheduler 具备"薄弱感知"——把分析结果反馈到出题调度中。

核心思路：
1. 从 `review_records` 找出得分 < 60 的薄弱知识点
2. 用 BM25 搜索与薄弱知识点语义相似的 KPs（薄弱扩散）
3. 优先调度这些"疑似薄弱"的 KPs 出题

## 问题（用户提出）

> "如果前面实在错得太多，会不会重复地考某一块题目？"

假设用户 30 个 KPs 里 15 个都弱，BM25 扩散扩散出来的相关 KPs 可能覆盖所有正常 KPs 的好几倍，导致：

```
GMP弱 → work stealing → 自旋线程 → P的数量 → 全局队列 → ...
                                         ↓ 下一轮
                                  GMP还是弱 → 又来一遍
                                         
                                  ⚠️ 其他 KPs 永远排不上
```

## 方案：双车道调度

把出题队列分成两条车道，2:1 交错合并：

```
 Lane 1（快车道）：薄弱 KPs + BM25 扩散发现的关联 KPs
 Lane 2（慢车道）：剩余所有正常 KPs（按原顺序）

 合并规则：
   从 Lane 1 取 2 个 → 从 Lane 2 取 1 个 → 回到 Lane 1
   直到两条车道都清空
```

### 硬约束

| 规则 | 说明 |
|------|------|
| 一轮一次 | 每个 KPs 每轮只进队列一次，不重复 |
| 按轮重置 | 所有 KPs 考完一遍后按最新成绩重建队列 |
| 快车道限流 | 2:1 比例保证至少 1/3 出题来自正常范围 |

### 效果

```
第一轮：
  [GMP弱→work stealing]  [正常KP#6]  [map弱→bucket]  [正常KP#7]  [defer弱→...]
   └─ Lane1 ─┘            └─ Lane2 ┘  └─ Lane1 ─┘      └─ Lane2 ┘  └─ Lane1 ─┘

第二轮（覆盖所有 KPs 后，重新计算）：
  [如果 GMP 提升到 70 分了] → 移出快车道
  [如果 map 还是 48 分]     → 留在快车道，继续扩散
```

### 数据流

```
review_records
     ↓ 聚合
薄弱 KPs 列表（avg < 60）
     ↓ BM25 语义搜索
关联 KPs（按 BM25 得分降序） →  Lane 1（快车道）
剩余正常 KPs（原顺序）      →  Lane 2（慢车道）
     ↓ 2:1 交错合并
出题队列
     ↓ scheduler 依次取
current_kp
```

### 为什么这样设计

1. **简单**——2:1 交错不需要复杂的优先级计算公式
2. **防饿死**——慢车道保证即使薄弱点很多，正常 KPs 也不会被无限推迟
3. **自适应**——提高后的 KPs 下一轮自动移出快车道
4. **可解释**——出题时能告诉用户"为什么考你这道题"
