# 为什么用 BM25 做 RAG 而不是别的？

## 一句话

我的项目用 BM25 做 RAG 检索，而不是向量检索或 LLM 直接生成，是**有意为之的设计选择**，不是为了炫技。

面试官问"为什么用 BM25"，关键是体现出你知道其他方案，并且知道它们在什么场景下更优、在你的场景下为什么不选。

---

## RAG 检索方案对比

| 方案 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **BM25（本项目使用）** | 关键词匹配 + 词频统计 | 精确、零依赖、可解释 | 不能理解语义近义词 |
| **向量检索（ChromaDB/FAISS）** | 把文本转成向量，算余弦相似度 | 能理解语义（"车"和"汽车"是近的） | 需要 embedding 模型、有额外依赖 |
| **TF-IDF** | 词频 × 逆文档频率 | 简单 | 没有长度归一化、没有参数可调 |
| **纯靠 LLM 知识** | 不检索，直接让 LLM 答 | 最省事 | 幻觉、看不到最新知识 |

---

## 为什么我选了 BM25

### 理由 1：面试展示价值

BM25 是我**手写**的。面试官问：
- "分词怎么做的？" → bigram，保持零依赖
- "k1 和 b 是什么意思？" → 控制 TF 饱和度和长度归一化
- "IDF 怎么平滑的？" → log(1 + (N - df + 0.5) / (df + 0.5))

每一条都能说清楚。如果用的是 ChromaDB，面试官问就只能答"我调了 ChromaDB 的 embedding API"。

### 理由 2：技术上有意降低依赖

向量检索需要：
- 一个 embedding 模型（要么调云 API，要么本地跑一个）
- 一个向量数据库（ChromaDB / Milvus / FAISS）
- embedding 模型对中文的理解质量，取决于你选的模型

BM25 只需要标准库 `math`，没有任何第三方依赖。

### 理由 3：对"知识点检索"这个场景，关键词匹配够用了

我的检索场景是：**出题时找到和当前知识点相关的其他知识点**。

八股文知识点之间的相关性，往往体现在**共享关键词**上：
- "GMP 模型"和"P 的作用"共享"P"这个关键词 → BM25 能准确找到
- "channel"和"goroutine 通信"共享"通信" → BM25 能找到
- 但"GMP 模型"和"调度器"如果不共享关键词 → BM25 找不到

最后这种情况，我的项目中不太需要——出题不需要跨域联想。

### 理由 4：BM25 是确定性算法

```
同样的文档 + 同样的查询 → 每次都返回同样的结果
```

而向量检索的 embedding 模型有版本问题，换了模型结果不一样。BM25 没有这个问题。

---

## 向量检索什么时候更好

我也知道向量检索的优点。如果将来需要以下能力，我会加上：

1. **语义近似匹配**："goroutine 调度"应该匹配"GMP 中的 G 是怎么运行的"——即使不共享关键词
2. **跨语言检索**：英文问题和中文文档
3. **非结构化数据**：图片、代码片段等

这些场景 BM25 确实不如向量检索。方案我也了解——加一个 ChromaDB 做 embedding，跟 BM25 做**混合检索**（BM25 结果和向量结果加权融合），是业界标准做法。

## 后续升级：Hybrid Search

2026-07-24，项目数据量增长后，在 BM25 基础上叠加了向量检索，升级为 Hybrid Search 混合检索。

详见：[RAG升级：从 BM25 到 Hybrid Search](2026-07-24-RAG升级混合检索.md)

升级要点：

- BM25 通路完全保留作为精确匹配层
- 叠加 `bge-small-zh-v1.5` embedding 做语义扩展
- 0.7 BM25 + 0.3 向量 加权融合（benchmark/run_rag.py 实测，召回优先）
- embedding 模型加载失败时自动降级到纯 BM25

## 所以面试时怎么答

> "我选 BM25 做 RAG 而不是向量检索，三个原因。
>
> 第一，这个项目的知识库是八股文知识点，文本短、关键词密集，BM25 的关键词匹配够用了，不需要 embedding 的语义理解能力。
>
> 第二，BM25 是我手写的，从 bigram 分词到公式实现，每一行代码我都能讲。如果用 ChromaDB，面试官问底层就只能说'调了 API'。
>
> 第三，BM25 零依赖，不需要额外部署向量数据库和 embedding 模型，部署成本低。
>
> 当然我也知道向量检索的优势——语义匹配。如果项目数据量变大、或者需要处理非结构化内容，我会加一层向量检索做混合检索，BM25 做精确匹配，向量做模糊匹配，两者互补。"
